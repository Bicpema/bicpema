# スキル高品質化スキル

## 目的

`.claude/skills` 配下のスキルを、実際の利用で起きた失敗・手戻りを根拠に改善します。

## 前提

- 改善の根拠は推測ではなく実績に置きます。利用実績（`/plugin` の Stats）、auto-memory の `feedback` 系ファイル、対象スキルを使った PR・Issue のレビュー指摘を根拠とします。
- 反映前に、変更案（対象・変更前後・根拠）を提示してユーザーの合意を得ます。
- Git 操作（commit・push・PR 作成）は本スキルの実行者（Claude Code本体）が行います。
- 共通ルールは `AGENTS.md` に置き、スキルには作業手順だけを書きます。
- 1 回の実行で対象にするスキルは、原則 1〜3 件に絞ります。

## 手順

1. 対象を決めます。引数がなければ使用回数の多いスキルを候補として提示し、ユーザーが選びます。
2. 対象の `SKILL.md` を全文読み、関連する memory の `feedback` を確認して、手戻りの原因になった手順の抜け・曖昧さを列挙します。
3. 次の観点で点検します。
    - description: 「何をするか」と「いつ使うか」があり、他スキルと使い分けられるか。`name` がディレクトリ名と一致するか。
    - 手順: 1 ステップ 1 アクションで、順序と分岐条件が明確か。「適宜」など判断に迷う表現がないか。
    - 安全性: 削除・push・マージなど取り消しにくい操作の前に確認があるか。禁止事項が明記されているか。
    - 検証可能性: 完了条件がチェックボックスで列挙されているか。
    - 重複: `AGENTS.md` や他スキルと同じルールを再記述していないか。
    - 参照: 相対リンクとパス・コマンドが実在するか。
4. 点検結果を Critical / High / Medium / Low の重大度順に、対象・問題・根拠・変更案とともに提示します。
5. ユーザーの合意を得た項目だけを `SKILL.md` に反映します。
6. `npm run lint:md` を実行し、書式違反がないことを確認します。
7. 変更内容と根拠を報告し、必要なら `pr-create` に切り替えます。

## 非対象

- `AGENTS.md`・エージェント定義の全体点検（`docs-drift-check` を使用します）。
- 本番コード・docs の修正。

## 完了条件

- [ ] 改善した各項目に根拠が示されている
- [ ] 反映前にユーザーの合意を得ている
- [ ] `npm run lint:md` が通っている
